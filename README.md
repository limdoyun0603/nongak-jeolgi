# 판굿 절기

24절기에 맞춰 고창농악 판굿이 쉬지 않고 도는 웹 작업. 지금은 엔진만 있고, 화면은 확인용이다.

## 무엇을 하는가

- 접속한 시각의 절기를 브라우저가 직접 계산한다.
- [nongak-formations](https://github.com/limdoyun0603/nongak-formations)의 판굿 녹화본을 끝없이 잇는다. 지금은 확정된 녹화본(입장굿)을 `data/`에 복사해 고정해 두고 그것만 쓴다. 원래 레포는 계속 바뀌므로, 디자인을 만지는 동안 데이터가 흔들리지 않게 하기 위해서다. `src/pan.js`의 `MODE`를 `'live'`로 바꾸면 원래 레포의 최신 녹화본을 매번 읽는다.
- 절기에 따라 판의 빠르기와 색이 바뀌고, 고창의 실제 해 높이에 따라 밝기가 바뀐다.
- 판의 진행은 현재 시각에서 계산한다. 같은 순간에 접속한 사람은 모두 같은 장면을 본다.

## 절기 계산

절기는 태양의 겉보기 황경이 15°의 배수가 되는 순간이다. VSOP87 축약식(Meeus, *Astronomical Algorithms*)으로 태양 황경을 구해 절입 시각을 찾는다. 2026년 24절기를 한국천문연구원 발표 시각과 비교했을 때 차이는 최대 1분이었다.

천문연 API를 매년 받아오는 방식도 검토했지만, 인증키 관리가 필요하고 API가 바뀌면 조용히 멈출 수 있어 계산 방식을 택했다.

## 절기별 변수

| 변수 | 근거 |
|---|---|
| 빠르기 | 작가의 해석. 농사일이 바쁜 망종 무렵 1.3배, 땅이 쉬는 대한 무렵 0.6배. 값은 `src/season.js`의 표에서 고친다 |
| 따뜻함 | 대한(大寒)을 가장 춥게, 대서(大暑)를 가장 덥게 두고 그 사이를 이은 계절감. 실제 기온이 아니다 |
| 밝기 | 고창(북위 35.4°, 동경 126.7°)의 실제 해 높이 |

판굿 원형에는 절기별 빠르기가 없다. 빠르기 배정은 이 작업의 해석이다.

## 구조

```
index.html
src/jeolgi.js   절기 계산
src/sun.js      고창의 해 높이
src/season.js   절기별 빠르기·따뜻함, 판의 가상 시간
src/pan.js      녹화본 불러오기, 구간 잇기, 시각 → 자세
src/main.js     확인용 화면 (최종 디자인은 이 파일만 바꾼다)
```

빌드 도구 없음. 정적 페이지로 GitHub Pages에서 돈다.

## 녹화본 순서

고정 모드에서는 `data/index.json`에 적힌 순서를 따른다. 실시간 모드에서는 `nongak-formations/recordings/index.json`이 있으면 그 순서를 따른다. 없으면 파일 이름에 `ipjang`, `madang1`, `madang2`, `madang3`이 들어간 순서로 놓는다.

```json
["ipjanggut.json", "madang1.json", "madang2.json", "madang3.json"]
```

## 한계

- 진형 기록기는 버튼으로 바꾼 진형을 녹화하지 않아, 녹화본 사이에 사람들이 순간이동하는 지점이 있다. 그 사이는 직선으로 잇는다. 줄을 따라 움직이는 이음은 아니다.
- 녹화본 목록을 GitHub API로 읽는다. API는 접속자 한 사람당 시간당 60번까지라 보통은 문제없지만, 한도를 넘으면 알고 있는 녹화본(입장굿)만 불러온다.

## 데이터
